VSpeak glasses 2

Robust replacement for the app "VSpeak glasses": shows telemetry values on ActiveLook glasses such as the ENGO 2 through the VSpeak glasses module on P1 (COM1). Same protocol as the original.

Difference to the original

The original only answers a request from the module if it arrives in exactly one piece. Fragmented or merged requests (about 5 % measured on the transmitter) stay unanswered and the values on the glasses freeze. VSGL2 reassembles the requests in a buffer.

Requirements

  • Transmitter with COM1 on P1 (DC/DS-24, DS-12)
  • VSpeak glasses module on P1, ActiveLook glasses
  • Only one app may use COM1: deactivate "VSpeak glasses" in the model.

Settings

The app menu is in German; the German label is given in brackets.

  • Page switch (Seiten-Schalter): selects the glasses page
  • Pages (Seiten): "3 (Mitte = 2)" for a 3-position switch (pages 1, 2, 3) or "2 (Aus 1, Ein 2)" for a 2-position switch (off = page 1, on = page 2)
  • BLE (On/Off): Bluetooth of the module on/off
  • Minus signs, show units (Einheiten anzeigen): as in the original
  • Edit page (Seite bearbeiten): which page is set up below (follows the page switch)
  • Source (Quelle): "Sensoren" (3 freely chosen sensors), "XC-Flight 1" (distance, average speed, flight time) or "XC-Flight 2" (altitude, entry timer, ENL)
  • Font size: small/middle/large per slot
  • Key 1 (Taste 1): forget the glasses stored in the module (when changing glasses)

The "XC-Flight" pages need the app XC-Flight running; otherwise the glasses show "-//-". The entry timer shows "--" (ready), 10…1 s, "OK" (flight), "X" (invalid) or "END" (motor after 30 min).

Diagnostics

Telemetry window "VSGL2 Diagnose": requests, answers, fragmented, merged, junk bytes, errors, longest gap, gaps over 1 s, last request, memory.
